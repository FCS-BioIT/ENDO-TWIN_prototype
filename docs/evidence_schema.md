# Relation-level evidence provenance schema

## Why a companion table, not a column change

`models/superset/adoc-literature-superset-v0.3.0/edge_evidence.tsv` is
generated by `build_edge_evidence()` in
`src/dt_adoc/model/superset_family.py` and consumed, by exact column name,
by `runtime.py`, `runner.py`, `dynamics.py`, `render_dynamics.py`,
`config/visualization.yaml`, and several tests. Its key is one row per
`edge_id`. That is a hard structural constraint of every consumer: it
cannot hold more than one evidence assertion per edge without breaking all
of them, and it was never designed to distinguish multiple distinct papers,
species, or experimental systems supporting the same edge.

The requirement here — allow multiple evidence assertions per edge without
collapsing distinct papers, species, or systems into one row — is a 1:N
relationship. The columns of `edge_evidence.tsv` were therefore left
untouched, and a new, single canonical relation-provenance table was added:

`models/superset/adoc-literature-superset-v0.3.0/edge_evidence_assertions.tsv`

keyed by `edge_id` as a foreign key into `edge_evidence.tsv`, with many rows
allowed per edge. No other file holds this information; `edge_evidence.tsv`
keeps exactly the columns and one-row-per-edge shape its consumers expect,
and its existing `evidence_id`/`confidence`/`variant_id` columns are
untouched by this work.

The table is generated by `migrate_edge_evidence()` and read/validated by
`load_assertions()` / `validate_assertions()` in
`src/dt_adoc/evidence/assertions.py` (module docstring there gives the
implementation-level rationale). `pixi run validate-evidence-assertions`
regenerates the file from source and validates it in one step.

## Columns

| Column | Meaning |
| --- | --- |
| `assertion_id` | Stable, deterministic id: `ASRT-<edge_id>-<n>` |
| `edge_id` | Foreign key into `edge_evidence.tsv` |
| `evidence_origin` | Where the assertion comes from (vocabulary below) |
| `reference_id` | `REF-*` id from `context/literature/references.tsv`, for bibliographic assertions |
| `source_observation_id` | `SOFIA-*` id from `context/evidence-register.tsv`, for in-house assertions |
| `species_evidence` | Species the *evidence itself* was generated in — copied from the cited reference or in-house record, never inferred from node/edge identity |
| `target_species` | The model's declared target organism: always `human` for this family |
| `species_transfer_required` | Mechanical flag: does `species_evidence` name a non-human organism while `target_species` is human? See below |
| `species_transfer_rationale` | Human-authored justification for why (or whether) the cross-species transfer is valid; required once curated |
| `compartment` | Tissue/compartment context of the evidence |
| `experimental_system` | Study type / system the evidence was generated in |
| `directness` | `direct` / `indirect` / `composite_or_inferred` / `unknown` |
| `support_type` | `perturbational` / `genetic` / `pharmacological` / `biochemical` / `functional` / `associative` / `descriptive` / `unknown` |
| `evidence_grade` | `A`–`E` or `not_yet_graded` |
| `direction_supported` | `supported` / `not_assessed` / `contradicted` |
| `context_dependence` | Free-text note on conditions under which the assertion holds, if curated |
| `implementation_class` | Reuses the repo's existing implementation-class vocabulary (see below); all 93 migrated edges are `executable_core` |
| `curation_status` | `not_yet_curated` / `curated` / `disputed` |
| `support_rationale` | Human-authored summary of why the evidence supports the edge as encoded, once curated |

### Controlled vocabularies

- `evidence_origin`: `bibliographic` \| `in_house_experiment` \| `database` \| `expert_assumption` \| `model_structure`
- `directness`: `direct` \| `indirect` \| `composite_or_inferred` \| `unknown`
- `support_type`: `perturbational` \| `genetic` \| `pharmacological` \| `biochemical` \| `functional` \| `associative` \| `descriptive` \| `unknown`
- `evidence_grade`: `A` \| `B` \| `C` \| `D` \| `E` \| `not_yet_graded`
- `direction_supported`: `supported` \| `not_assessed` \| `contradicted`
- `curation_status`: `not_yet_curated` \| `curated` \| `disputed`
- `implementation_class`: `executable_core` \| `uncertain_rule_variant` \| `catalog_only` \| `external_boundary` \| `phenotype_or_logical_aggregate` \| `physiboss2_coupled_model_later` \| `unsupported_candidate` \| `deprecated`

### The `species_transfer_required` flag is mechanical, not a scientific judgement

`species_transfer_required` is computed by pattern-matching the already-copied
`species_evidence` text for `mouse`/`mice`/`murine`/`rat`/`rats`/`baboon`/
`non-human` and is set to `"true"` whenever one of those appears while
`target_species` is `human`. This is deliberately *not* a biological
assessment of whether the transfer is valid — it exists solely so that
non-human evidence can never silently pass as human evidence by defaulting
to an unlabeled/unknown state. The actual judgement — whether the mouse or
baboon finding transfers to the human ADOC context, and why — is left to
`species_transfer_rationale`, which stays empty until a human curator fills
it in (`validate_assertions` only requires it once `curation_status` moves
past `not_yet_curated`).

## Conservative migration of the 93 executable edges

`migrate_edge_evidence()` walks every row of `edge_evidence.tsv` (93 rows,
unchanged) and emits one or more assertion rows, with no new biological
content invented:

- `SOFIA-*` evidence ids → one `in_house_experiment` assertion.
  `source_observation_id` is the SOFIA id; `species_evidence` and
  `compartment` are both copied from that record's `system` field in
  `context/evidence-register.tsv` (not derived from the node dictionary).
- `LIT-*` evidence ids → one `bibliographic` assertion **per** `REF-*` id
  the `location` column of `context/evidence-register.tsv` lists for that
  LIT id (semicolon-separated). A LIT id citing 5 references — e.g.
  `LIT-SPP1-001` → `REF-007;REF-015;REF-017;REF-022;REF-038` — produces 5
  separate assertion rows per edge, one per paper, never one combined row.
  `species_evidence` and `compartment` are copied per-reference from
  `context/literature/references.tsv`, not from the LIT id's aggregate
  record and never from node species.
- Every migrated field the migration cannot derive mechanically is left at
  an explicit placeholder: `directness=unknown`, `support_type=unknown`,
  `evidence_grade=not_yet_graded`, `direction_supported=not_assessed`,
  `curation_status=not_yet_curated`, `context_dependence`/
  `support_rationale`/`species_transfer_rationale` empty.
- `implementation_class=executable_core` for all 93 edges (preserved from
  the fact that they are already in the executable edge table — not
  re-derived).
- The existing `confidence` column in `edge_evidence.tsv` is **not** copied
  or mapped onto `evidence_grade`. Confidence stays exactly where it already
  lived; grading is a separate, still-unperformed curation step.
- No edge is promoted or demoted, and no field is filled in just because it
  looked fillable.

Migration is deterministic (`assertion_id = ASRT-<edge_id>-<n>`, stable
input ordering) and idempotent: running `migrate_edge_evidence()` twice
against unchanged sources produces a byte-identical file.

## Validation (`validate_assertions`)

`pixi run validate-evidence-assertions` regenerates and checks:

- every executable edge in `edge_evidence.tsv` has at least one assertion;
- every assertion's `evidence_origin` is in the vocabulary;
- `bibliographic` assertions have a non-empty `reference_id` that resolves
  in `context/literature/references.tsv`;
- `in_house_experiment` assertions have a non-empty `source_observation_id`
  that resolves in `context/evidence-register.tsv`;
- non-human `species_evidence` with `target_species=human` must have
  `species_transfer_required=true`; if `species_transfer_required=true`
  then `species_transfer_rationale` must be non-empty, unless
  `curation_status=not_yet_curated` (uncurated rows may be incomplete, but
  must be visibly, explicitly uncurated — never silently complete);
- `directness` and `support_type` must not be `unknown` once
  `curation_status=curated`;
- `not_yet_curated` rows are counted and reported in the summary, never
  treated as complete;
- every `edge_id` referenced by an assertion exists in `edge_evidence.tsv`;
- `assertion_id` values are unique.

## Migration report (current state)

Counts from the 93-edge migration, as of the last `pixi run
validate-evidence-assertions` run at the time of the migration (294 assertion rows
total). **Superseded twice:** commit `c0c64dd` retracted 22 citations and attached 2,
taking the table to 274 rows; curation increment 7 then retracted a further 10 and
attached 3, so the current table has **267** rows. The distribution below is the
migration-time record and is left as written:

| Category | Count | What it means |
| --- | --- | --- |
| Citation identity verified (reference_id resolves in the bibliography) | 277 | Every bibliographic assertion's `REF-*` id exists in `context/literature/references.tsv`; this proves the citation is real, not that it supports the edge |
| Reference linked (assertion carries a `reference_id` at all) | 277 | All 277 bibliographic assertions; equals citation-identity-verified here because every migrated reference_id was checked against the bibliography |
| Edge-level biological support manually verified | **0** | No human has yet reviewed whether any cited paper or in-house observation actually supports the specific edge direction/sign as encoded. This is the work `curation_status=curated` will represent once performed — it does not exist yet |
| In-house experimental support (`evidence_origin=in_house_experiment`) | 17 | SOFIA-sourced assertions, one per edge citing a SOFIA evidence id |
| Species transfer reviewed (`species_transfer_rationale` authored by a curator) | **0** | 127 assertions are mechanically flagged `species_transfer_required=true` because their copied species text names mouse/rat/baboon evidence applied to a human target model, but none of those flags have yet been reviewed or rationalized by a curator |
| Not yet curated (`curation_status=not_yet_curated`) | 294 | All 294 assertions — the entire migrated set is uncurated by construction; this migration only relocates and structures existing evidence identifiers, it does not adjudicate them |

The two zero rows are expected and intentional: this migration is a
structural, conservative relocation of already-declared evidence
identifiers into a queryable 1:N shape. It verifies that citations exist and
resolve; it does not — and must not appear to — assert that any of them
have been read and confirmed to support the specific edge, direction, or
species context encoded in the model. That review is future curation work,
tracked here via `curation_status` and `species_transfer_rationale`, not
performed by this change.
