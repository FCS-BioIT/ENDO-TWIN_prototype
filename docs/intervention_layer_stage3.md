- The v0.5.x increments (v0.5.1 by `u5b_increment`, v0.5.2 by `v052_increment`)

## 5. Projection between the state spaces

The deleted nodes are constant within every phase. A v0.5.2 state therefore maps
to the v0.6.0 state with the same values on the 56 retained nodes:

    π : {0,1}^59 → {0,1}^56,  drop IN_MIFEPRISTONE, IN_ANTI_SPP1, IN_HAND2_LOSS

- Within a phase, the deleted nodes take one fixed value, so π is one-to-one on
  the states that phase can reach. A projected distribution is a relabelling,
  not a sum, and G8 checks that no two parent labels collapse onto one.
- Of the deleted nodes, only `IN_HAND2_LOSS` is tracked (`is_internal = FALSE`).
  It therefore appears in v0.5.2 state labels and in `nodes_probtraj`, and π
  removes it from both.
- The phase's intervention set is the image of its marker values. Take the
  markers' starting values in the phase, read the way the runner reads them
  (`_legacy_input_value`). Each marker that is ON maps to the library
  intervention whose `legacy_input_node` it is.

## 6. Protocol migration

**Decision: explicit v0.6.0 protocol rows in a new, declared post-closure file,
`config/protocols_markerless.yaml`, generated from the v0.5.2 definitions.**

- **Why not `config/protocols.yaml`.**
  - It existed when Phase 2B was closed, so any edit to it is reported as
    undeclared drift (`closure_replay.undeclared_drift`).
  - The closed Phase 1B builder reads its doses.
  - C3a binds its bytes at its pre-registration commit (`BOUND_PATHS`).

  Adding a v0.6.0 row there would edit a closed input.

  Adding a file under `config/` is the sanctioned route instead: declare it in
  `closure_replay.POST_CLOSURE_FILES` with its reason, as
  `config/intervention_library.tsv` was.
- **Why not a clone rule.** The superset clone layer copies the archived
  families' rows. Every row names the markers in `input_states`, including rows
  where they are OFF. O8a-1 records that names declared on an archived parent row
  would also be validated against the archived version. Explicit rows keep v0.6.0's
  schedule out of the archived families entirely.
- **Generated, not transcribed.** `v060_increment.protocol_rows()` writes each
  v0.5.2 definition out as a row, with three changes:
  1. `model_version` is v0.6.0, and `condition_cfg` points into the v0.6.0
     `conditions/`;
  2. the three markers are dropped from `input_states`;
  3. `interventions` lists the library ids whose marker that step sets ON.

  Step ids, durations, notes, evidence, comparator roles, `continuation_from`
  and continuation policies are copied unchanged. A test requires the committed
  file to equal the generator's output byte for byte. A second test requires each
  v0.6.0 definition to equal its v0.5.2 definition under the §5 mapping.
- **Resulting schedule** (the experimental schedule itself is unchanged):

  | protocol | step's interventions |
  |---|---|
  | `hormone_treated_mifepristone` (after `hormone_treated_maternal`) | `mifepristone` |
  | `adhesion_challenge_hormone_treated_mifepristone` | `mifepristone` (persistence) |
  | `hormone_treated_anti_spp1` | `anti_spp1` |
  | `adhesion_challenge_hormone_treated_anti_spp1` | `anti_spp1` (persistence) |
  | `washout` (after `hormone_treated_anti_spp1`) | none, so the veto is lifted (washout) |
  | `adhesion_challenge_washout` | none |
  | `hormone_treated_hand2_loss` (from `e2_primed_maternal`) | `hand2_loss` |
  | `adhesion_challenge_hormone_treated_hand2_loss` | `hand2_loss` (persistence) |
  | the other seven | none |

- **Loader rules.** Rows in `config/protocols_markerless.yaml` must name a
  superset version at or after `MARKERLESS_FROM_SUPERSET_VERSION = (0, 6, 0)`.
  - A version may not have rows in both files.
  - A superset version at or after that floor with no explicit rows is
    **refused**, rather than cloned from marker-bearing parents.
  - Every protocol resolution also checks that each `input_states` key is a node
    of the model. This holds today for all seven existing versions, which was
    checked before the rule was added. Without it, a stale marker name would reach
    MaBoSS as an istate for an undefined node.
- **Condition cfgs.** The v0.6.0 cfg files keep their v0.5.2 names, because
  protocols and the validator's smoke list address them by name. With the
  markers gone, `hormone_treated_mifepristone.cfg` has the same content as
  `hormone_treated.cfg`. That is correct: a cfg now carries biological and
  environmental inputs only, and the arm's intervention is in the protocol. A cfg
  run standalone outside a protocol is therefore untreated. No production code
  runs the `[condition_suite]` standalone. G8 covers it anyway by naming the
  interventions explicitly (§8).

## 7. Intervention-library migration and licensing

### 7.1 The decision

**A third mapping basis, `migrated_legacy_behaviour`, for rows of a version
whose marker was removed, licensed by exhaustive equivalence with the parent
version's `executable_legacy_behaviour` row.**

The alternatives, and why each was rejected:

- **`executable_legacy_behaviour` as is.** It requires a `legacy_input_node` in
  the model, and its licence is the Stage 2 check against that node's rule. On
  v0.6.0 there is no such node and no such rule, so the claim would be false.
- **`direct_supported_effect`.** It means "the cited evidence independently
  licenses this target and mode". The historical rows were never adjudicated
  that way. Their licence is that they reproduce the curated v0.5.2 rule. The
  loader would also accept them: the targets have roles `regulator` and
  `extracellular_bridge`, and the evidence ids resolve. So relabelling would pass
  validation while silently upgrading the claim, which is the outcome to avoid.
- **New intervention ids** (for example `mifepristone_v060`). These would make
  the protocol and every provenance record name a different intervention for
  the same reagent, and break the link to the parent row.

No column is added, which O8 also avoided. The claim "this effect equals
intervention X of the parent version" is carried by:

- `mapping_basis = migrated_legacy_behaviour`;
- the parent version, read from the child model's own
  `provenance.toml [increment] parent_model_version`, so the parent is never
  restated by hand;
- the same `intervention_id` in both versions.

### 7.2 Licence, checked when the library is loaded

A `migrated_legacy_behaviour` row is refused unless all of these hold:

1. **No marker in this version.** `legacy_input_node` and
   `legacy_perturbation_ids` are empty.
2. **Mode `activity_veto`.** No other mode is migrated in this unit.
3. **A legacy parent row exists.** The child's `[increment]` names a parent
   version. That version has rows for the same `intervention_id`, with basis
   `executable_legacy_behaviour`, the same label, class and mode, the same
   target set, and the same `evidence_ids` and `model_abstraction`.
4. **The parent's marker is gone.** It is not a node of the child network.
5. **Exhaustive rule equivalence, per target `t`.** Let `m` be the parent's
   marker, and `D` the parent markers absent from the child. Then:
   - **untreated:** `child_rule_t(x) == parent_rule_t(x, D := 0)` for every
     assignment `x`;
   - **treated:** `parent_rule_t(x, m := 1, D \ {m} := 0)` is false for every
     `x`, which is exactly what `activity_veto(child_rule_t)` renders.

   So the child's rendering, vetoed or not, is the parent's legacy rule with the
   marker ON or OFF. This is the Stage 2 check carried across one version step.
6. **Readable target, sources that exist.** The target passes `_target_logic`
   (one logic line, not an input, no rate), and every `abstraction_sources` file
   exists.

The static licence covers the rule. **G8 (§8) covers the dynamics**: the timing,
the continuation, the RNG and the whole lineage. A row is licensed for v0.6.0 by
both. The licence is checked on every load. G8 is a test of the committed
version.

### 7.3 Rows

- **Added:** `mifepristone` (`E_PGR`, `S_PGR`), `anti_spp1`
  (`X_SPP1_LUMEN_FREE`) and `hand2_loss` (`S_HAND2`) for v0.6.0, all
  `migrated_legacy_behaviour`. Their evidence ids and abstractions are the parent
  rows'. Their sources cite the parent's node dictionary entry for the marker,
  which still exists in v0.5.2, and the parent library row. Their claim boundary states
  the parent rule they reproduce.
- **Also added:** `xav939` for v0.6.0, unchanged in meaning: still
  `executable_legacy_behaviour`, `no_executable_effect`, with `IN_XAV939`, which
  v0.6.0 still has.
- **Unchanged:** every v0.5.2 row.

### 7.4 What changes in the loader

- One `intervention_id` may now have rows for several model versions.
  - Intervention-level fields are compared per `(id, version)`.
  - Label and class must agree across versions, since they describe the same
    reagent.
- Every lookup selects the rows of the requested version. A version with no row
  for a named id is refused as before ("not defined for this version").
- `named_effect_records` additionally records `parent_model_version` for a
  migrated row. Records of legacy and direct rows keep their exact shape.

## 8. G8 — the equivalence gate

**Primary criterion: same-seed exact equality after projection.** Parent is
v0.5.2 with its marker-timed protocols. Child is v0.6.0 with its name-timed
protocols. Both run the production `run_protocol` and `protocol_continuation`,
unpatched, on the repository root.

**Stage A — the Boolean transformation (no MaBoSS).**
1. For every node and for every assignment of the marker values, the composed
   function is compared over all free variables: 2^16 child assignments × 2^3
   marker values. The child's function, with the targets of the ON markers
   rendered by the engine, must equal the parent's function at those marker
   values.
2. For each phase of every lineage, the rendered network the child executes must
   be rule-by-rule equivalent to the one the parent executes, by exhaustive
   evaluation. The two must veto the same set of targets.
3. Each child merged cfg must equal its parent's merged cfg with the deleted
   nodes' lines removed, as text.

**Stage B — same-seed runs.**
- **Lineages.** All 15 v0.5.2 protocols, each chained from `basal_maternal` as
  `concordance.simulate.protocol_lineage` chains them. Together they cover:
  - the untreated and control paths;
  - mifepristone onset and persistence;
  - anti-SPP1 onset and persistence;
  - the anti-SPP1 washout and its challenge;
  - HAND2 loss through hormone treatment and into its challenge;
  - the two condition arms (ER stress, ECM stiffness).
- **Standalone conditions.** The 21 `[condition_suite]` conditions are also run
  as single phases. The child names the interventions whose marker the parent
  cfg sets ON.
- **Seeds:** 1, 2, 3. **Trajectories:** 1000 per run. **Time:** each step's
  declared `relative_duration` and the model's `time_tick`.
- **Compared, per phase, exactly:**
  - every column of `nodes_probtraj` after π, which is every node trajectory,
    phenotypes (`OUT_*`) included;
  - the last-node marginals;
  - the last-state distribution after π, with no label collapse;
  - the continuation handed to the next phase after π: memory nodes,
    distribution, policy, cutoff, retained and dropped mass, and forced nodes
    minus the deleted ones;
  - the set of vetoed targets and their rendered rules (equivalent by Stage A);
  - the phase structure: step ids, durations, `continuation_from`, policies and
    the protocol sequence.

**Fallback, pre-registered here and used only under stated conditions.**
Deleting nodes could in principle change MaBoSS's draw sequence. The fallback is
used only if all of these hold:

1. Stage A passes.
2. Stage B fails.
3. The failure is shown to be a draw-sequence difference rather than a semantic
   one. The evidence required is that the very first differing phase has an
   identical executed network and an identical initial distribution under π.

The fallback is fixed now, before any comparison is run:

- **Runs.** 20 000 trajectories per run, at seeds 11 to 15 for each version.
  The parent and child streams are treated as independent.
- **Per-node test.** For every phase and every retained node, compare the
  pooled last-node marginals. With N = 100 000 trajectories per side, a node
  fails if |Δp| > 5·√(2·p̄(1−p̄)/N) + 10⁻⁹. p̄ is the pooled mean of the two
  sides.
- **State test.** For every phase, the total-variation distance between the
  pooled projected last-state distributions must be ≤ 0.01.
- **Verdict.** Any failure fails G8.

The tolerance is not tuned afterwards. If the fallback is needed and fails, the
unit stops there and is reported.

**Negative controls.** Each must make G8 fail:

- **NC1 omitted:** `anti_spp1` is dropped from `hormone_treated_anti_spp1`.
- **NC2 not washed out:** `anti_spp1` is kept on in `washout`.
- **NC3 mistimed:** `mifepristone` is moved from `hormone_treated_mifepristone`
  to its challenge only.
- **NC4 a historical gate left in place.** This has two forms:
  - The conjunct is kept while the node is deleted. The structural assertions
    (§11) and Stage A both refuse that child. MaBoSS cannot load it either.
  - The node and the gate are both kept, with the marker held OFF. That is
    dynamically **inert**, since `and not 0` is the identity, so no dynamic
    gate can see it. It is caught by the structural assertion that no
    executable rule names a removed marker, and the record says which gate
    catches it.

**Not covered.** Marginal continuation mode crashes MaBoSS on both versions in
the pinned runtime (G7 records this). So, as there, its input-value rule is
covered statically only.

## 9. XAV939

**Decision: unchanged in v0.6.0.**

- `IN_XAV939` stays a node, with its `istate` lines and its `input_states`
  entries.
- Its library row is repeated for v0.6.0 with the same `executable_legacy_behaviour` /
  `no_executable_effect` meaning.

Why it is not removed here:

- Its row records the model's silence about a cocktail reagent, not a veto that
  needs migrating. No rule reads the node.
- The plan leaves O2 (keep it as a protocol-provenance node, drop it, or give it
  an effect if evidence licenses one) undecided. Removing it would decide O2
  implicitly.

What removing it cleanly would require, recorded for a later unit:

1. An O2 decision recording that the hormone cocktail's reagents are protocol
   content rather than biological inputs. `IN_cAMP` (O1) has the same shape and
   should be decided with it.
2. A way for the protocol to record a reagent with no executable effect. A step
   could name `xav939` in `interventions`, which O8a's parser already accepts for
   a `no_executable_effect` row once the marker is gone.
3. A library basis for a markerless `no_executable_effect` row. Neither existing
   basis allows one, and §7.2 rule 2 deliberately does not migrate that mode.
4. A G8-style gate. Because the node is unread, this would be a pure projection.
   Removing it also changes the free-variable count (2^16 → 2^15) and the input
   count again, so the structural tables would move a second time.

## 13. Non-goals, failure criteria, rollback

**Non-goals:**

- real compounds;
- a screen or Stage 4b;
- activation modes, partial engagement, dose, pharmacokinetics;
- `dropout_e2`, D2/D3;
- any archived version;
- XAV939 and cAMP (§9);
- repointing any analysis to v0.6.0;
- a repo-wide `release()` migration. New Stage 3 loops use `with` or `release()`.

**Failure criteria**, any of which stops the unit:

- Stage A fails and the generator cannot be shown to be at fault.
- Stage B fails for a reason that is not a draw-sequence difference.
- The fallback fails.
- A negative control passes G8.
- Any v0.5.2 or archived byte changes.
- Closure replay or `undeclared_drift` fails.

**Rollback.** The unit is additive:

- delete `models/superset/adoc-literature-superset-v0.6.0/` and
  `config/protocols_markerless.yaml`;
- delete the v0.6.0 library rows;
- revert the loader and consumer edits.

v0.5.2 and every result computed on it are untouched throughout.

The fall from 35 to 29 functions and from 8 to 7 classes is not a change of
biology. It is the parent's functions with the markers held OFF, which is what
Stage A proves equal.

- With no veto available in the network, `E_PGR`, `S_PGR` and `S_HAND2` compute
  the same function as `IN_PROGESTIN`.
- `E_RECEPTIVE_SURFACE` and `OUT_EPITHELIAL_RECEPTIVE` join the LIF class.

So the v0.6.0 counts describe the **unperturbed** network's structure and
identifiability. They are not a bound on distinguishable screened
interventions. An intervention renders a different network, and can break a
baseline alias: the engine's vetoes separate `E_PGR`, `S_PGR` and `S_HAND2` from
`IN_PROGESTIN` again, as the markers did. Combinations are not bounded by the
number of singleton baseline functions either. A perturbational-equivalence
bound would have to be computed and proved over the rendered networks; none has
been (plan O6).

**Defects found and fixed in this unit:**

- `run_structural_smoke` could not write `protocol_phases.tsv` for a name-timed
  protocol. `protocol_sequence` adds `interventions` only to the steps that
  declare some, so the rows were ragged and `csv.DictWriter` refused them. The
  column is now on every row when any row has it. A marker-timed smoke's table
  keeps its exact shape.
- The smoke manifest's `declared_in` and the dynamics metadata's protocol
  `definition` always named `config/protocols.yaml`. They now name the file the
  version's rows come from.
- `structure.py`'s bitwise evaluator mis-reads numeric literals: `not 1` becomes
  `~1`, which clears bit 0 only. It is not used on rendered networks anywhere.
  Stage A therefore uses a literal-safe evaluator of its own. The latent issue
  in `structure.py` is recorded and not changed, because that file is in the
  implementation digest.
