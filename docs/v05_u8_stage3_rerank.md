# U8 — Stage-3 experiment rerank against adopted v0.5.1

**Status: COMPLETE (2026-09-24, `feat/v05-u8-stage3-rerank`). Result: `dropout_e2`
remains first. The v0.5.1 Stage-3 computation is identical to v0.4's in every
quantity the ranking reads.** No model, no observation map and no frozen Stage-3
artifact was modified, and no model version was created.

Generated artifacts, regenerated byte for byte with `pixi run build-u8-stage3-rerank`:
[`experiments/u8_stage3_rerank/`](experiments/u8_stage3_rerank/). The generated
[`u8_rerank_report.md`](experiments/u8_stage3_rerank/u8_rerank_report.md) and
`u8_rerank_summary.json` are the source of every count. This record does not
restate them. Guards: `tests/unit/test_v05_u8_stage3_rerank.py`.

## 1. Why this unit exists, and what it is conditional on

`docs/scrna/node_support_finding.md` §8 made the rerank mandatory and declined to
predict its outcome. Plan §0.7 and §14 record the condition, and U8 carries it
unchanged:

- The mandate rests on `AC01` being `alias_challenged`.
- That verdict depends on **D1**, a post-extraction interpretive call about the
  direction-vote guard, which is registered as `post_extraction_semantic_repair`.
- Under the recorded counterfactual without D1, `AC01` is
  **`unclassified_by_section_5_4`**, and the rerank would be optional rather than
  owed.

The condition is read from the machine-readable decision provenance in
`docs/scrna/node_support_findings.json` (`alias_classes.AC01.decision_provenance`)
at build time. It is copied into the summary under `d1_dependency`, together with
that file's digest. If the record ever stops saying this, the summary reports
`D1_CONDITION_NOT_AS_RECORDED` instead of the mandate. **U8 does not re-adjudicate
D1.** So the rerank is downstream of a protocol call, not of a raw measurement.
Here that costs nothing, because the answer is the same either way (§4).

## 2. What was run — the §14 protocol, and nothing wider

| §14 item | How it is met |
|---|---|
| 1. Touch no v0.4 artifact; write to a v0.5 output directory | Output goes only to `docs/experiments/u8_stage3_rerank/`. The four frozen Stage-3 files are digest-pinned to literals, and the default generator is asserted to regenerate them byte for byte. |
| 2. Same code, same readout-tier computation | `stage3_design.evaluate(root, model_version)`. The version is the **only** new parameter. The forks, the sixteen experiments, their curated declarations and `_readout_tier` are the same objects for both models. Tiers come from `config/observation_model_map.tsv`. `config/candidate_score.yaml` is **proven never opened**: the test records every file open during the computation. |
| 3. Frozen v0.4 ranking, v0.5 ranking, per-arm delta | The three reported objects (§3 below). |
| 4. The 112-arm design-alias comparator | **Not recomputed.** §14 says reusing it "is a deliberate methodological change that needs stating — not a free cross-check". U8 is the Stage-3 rerank, and the comparator remains `docs/design_alias_note.md`, which was computed by a different method. |
| 5. Does `dropout_e2` still rank first? | Yes (§4). |
| 6. The frozen result is never rewritten, nor retro-justified | The v0.4 side is **parsed from the committed frozen TSV**. The build refuses to run if a fresh v0.4 evaluation no longer reproduces that file. A test drives the negative branch (§5). |
| 7. `E_PAEP` interpretation rule | Met on 2026-09-17 (`stage3_experiment_selection.md` §9.1). The rerank does not use it. |

**The Stage-3 generator change is minimal and preserves the historical output.**
Only three things changed:

- `evaluate` takes `model_version`, defaulting to `MODEL_VERSION` (still v0.4.0), and records it in the report.
- `render` takes the name of the regenerating task for its banner.
- `render_tables` now **refuses** any other model, because its prose argues about v0.4 by name.

`pixi run build-stage3-design` still writes exactly the committed bytes.

**U7 was not needed.** Stage 3 evaluates exact Boolean marginals over the latent
free variables. Mechanism classes are in-memory rule substitutions, and
interventions are input assignments or clamps on the evaluated network. Nothing
in the computation reads a MaBoSS `$`-parameter or a mutation interface, and no
MaBoSS campaign was run.

## 3. The three reported objects — what "three rankings" means

§17's "Three rankings reported" and §14 item 3 were written in the same commit
(`2d6fc30`). Item 3 lists exactly three reported objects: the frozen v0.4
ranking, the v0.5 ranking and the per-arm delta. That is the reading used here.
The other possible reading is that the design-alias comparator is a third
ranking. §14 item 4 rules that out explicitly, so it was not adopted. **This is an
interpretation of the specification and is flagged as one.**

**Stage 3 never produced a scalar score, and U8 does not invent one.** The frozen
ordering is `stage3_experiment_selection.md` §3 and §6 arguing over computed
columns and curated cost declarations:

- `dropout_e2` recommended;
- `smo_antagonist` runner-up;
- `dropout_camp` third, and explicitly not recommended;
- `observe_e2_primed` a prerequisite registration, not an arm to run.

Re-scoring those positions would be exactly the new criterion U8 must not add.
The rerank does something narrower instead:

1. **Frozen v0.4 ranking.** The curated positions above, quoted with their
   sections, and the candidate set, meaning the arms that separate a fork on a
   usable assay. The candidate set is derived from the frozen TSV.
2. **v0.5.1 ranking.** The same derivation applied to the v0.5.1 TSV. In
   addition, **each computed premise the frozen ordering cites is re-evaluated
   on both models** as a value, not as a pass or fail. There are ten premises,
   each already pinned for v0.4 by `test_stage3_design.py`. If every premise is
   unchanged, the ordering carries over (`CARRIED_OVER_UNCHANGED`). If any one
   moves, the build withholds an ordering and reports `READJUDICATION_REQUIRED`.
3. **Per-arm delta.** Every profile column for every arm, on both models, with
   the fields that changed. The same comparison is made per class pair in
   `pair_separation_delta.tsv`, which also flags any change in the predicted
   values themselves.

## 4. Result

Read the numbers in
[`u8_rerank_report.md`](experiments/u8_stage3_rerank/u8_rerank_report.md). In
words:

- **`dropout_e2` remains first.** Every premise is unchanged, and the ordering
  carries over without re-adjudication.
- **No arm changed position and no arm changed any field.** The candidate set is
  the same.
- **No mechanism-pair separation changed, and no usable-readout separation
  changed.** Beyond what Stage 3 itself compares, the **exact marginal of every
  node** was compared for every experiment × mechanism class on both models, and
  none differs. That covers the embryo-side and unassayed nodes too, so
  "separable in model state" is unchanged as well as "separable on a usable
  assay". This is identity of **per-node marginals**, which is the quantity
  Stage 3 compares. It is not a claim that the joint state distributions are
  identical, which were not compared.

**Cause attribution, in the four categories asked:**

| Candidate cause | Finding |
|---|---|
| U5b's executable rule change | Present, and **invisible to Stage 3**. `OUT_STROMAL_DECIDUALIZED` goes from `S_DECIDUALIZED and S_PRL and S_IGFBP1` to `S_DECIDUALIZED`, retiring the `S_PRL` and `S_IGFBP1` dependencies. Both markers compute `S_DECIDUALIZED` in both models, so the two rules are the same function unless a marker is forced independently. No Stage-3 class rewrites either marker and no Stage-3 arm sets or clamps either one. U5b's own measured difference was a MaBoSS **transient**, which exact Boolean evaluation does not read. |
| Changed model structure | Present, and **does not enter**. In v0.5.1 `S_PRL` and `S_IGFBP1` become phenotype-inert **under clamping**, and no Stage-3 intervention clamps them. `S_IGFBP1` is still read as a *readout*, with the same value in both models. |
| Altered alias classes | **None.** The classes and the distinct-function count are identical. |
| Bookkeeping only | The one differing line of the rendered v0.5.1 design is its generated-file banner, which names the model and task. |

**What this does not mean.** It is not a re-validation of the frozen choice. It
shows that the move to v0.5.1 changed nothing Stage 3 reads, so the frozen
argument stands on v0.5.1 exactly as far as it stood on v0.4, and no further.
Every residual ambiguity in `stage3_experiment_selection.md` §7 is untouched. In
particular:

- `SEC-a` against `SEC-e` is still unreachable at a readout that exists.
- The `AC01` members still share one function in v0.5.1.

The audit's §8 concern, that `E_PAEP` and `E_HBEGF` might be distinct states, is
therefore **not represented in the adopted model**, because U3 found no derivable
rule. A minus-E2 arm still moves one thing in v0.5.1, just as it did in v0.4.
That is why the rerank returns identity. It would have to be rerun if a later
model broke `AC01`.

**Consulted.** Whether to carry the ordering over (as done here) or to
re-adjudicate it was put to an independent Codex consultation (`aih consult`,
2026-09-24). It recommended carrying it over, explicitly conditional on the
frozen Stage-3 criteria and not as a renewed endorsement, with high confidence.
It named three things that would change that:

- a changed qualitative §3/§6 premise, assay feasibility or evidence-gap
  assessment;
- a fresh run showing any difference;
- the owner stating that U8 was meant to reconsider the decision criteria
  themselves.

None applies on the record as it stands. The last one is the owner's call. The
consultation also corrected an overstatement: an earlier draft here said "full
state", which the marginal comparison does not establish.

## 5. Guards

`tests/unit/test_v05_u8_stage3_rerank.py`:

- **Frozen artifacts.** They are digest-pinned to literals, and the default
  generator still regenerates them.
- **v0.4 tables.** They refuse to render for another model.
- **Frozen reference.** A drifted reference stops the rerank.
- **Configuration lineage.** Every file the computation opens under `models/`
  or `config/` is recorded with its current SHA-256 in the summary. The guard
  checks this against the files actually opened.
- **Models.**
  - No file under `models/` is modified and no model directory is created. The
    directory set is pinned.
  - The computation opens nothing for writing.
  - The v0.5.1 `network.bnd` is the file actually read.
- **Scoring inputs.**
  - `candidate_score.yaml` is never opened, and `observation_model_map.tsv` is.
  - The tiers equal `_readout_tier` and are identical across models.
  - The scRNA map carries no active status, so it cannot promote a tier.
- **Candidate set.** The experiment and fork sets are pinned to the frozen ones,
  and the (experiment, fork, pair) grid is identical.
- **U6b isolation.**
  - No Stage-3 class or arm touches a U6b catalogue node.
  - The split's new nodes do not exist in v0.5.1.
  - `E_MUC1_BARRIER` is still the frozen rule.
- **Determinism.**
  - Committed outputs equal a fresh computation, and two computations are
    identical.
  - The build is registered in the clock-frozen determinism test.
- **Reconciliation.** Per-arm deltas and pair deltas reconcile with the two
  design TSVs.
- **The answer.**
  - It is pinned as a result.
  - A moved premise withholds the ordering (`READJUDICATION_REQUIRED`).
  - Each premise is evaluated on both models.
- **Cause.** The only rule change is U5b's, and Stage 3 cannot see it.
- **D1.** It is carried from the findings file, and an altered D1 record is not
  reported as the mandate.
