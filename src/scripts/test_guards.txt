# Integrity and provenance guards run by `pixi run test-guards`.
#
# One unittest TestCase per line, named as `unittest discover -s tests` names it.
# Blank lines and `#` comments are ignored.
#
# These guards check integrity and provenance only. They do not protect
# scientific behaviour in general and they do not replace the complete suite:
# `pixi run test` is still the required pre-merge check.
#
# Membership was measured in the 2026-10-15 verification audit (baseline 9b9bf5b).
# These classes held every test that caught the injected regressions M1-M5:
# stale implementation provenance, a new CRLF file, PCSK5 -> PCSK6 in the live
# corrected map, an edited frozen Phase 1B artifact, and a changed table left
# beside a stale figure. The cheap global, frozen-pin and provenance classes
# around them are included too. Each class runs in a few seconds.
#
# Excluded on purpose (they stay in the complete suite):
# * unit.test_c3a_kinetic_readout.GeneratorInventoryIsImmutable writes a probe
#   file into the live src/dt_adoc/ and needs HEAD~1, which a parentless review
#   snapshot does not have.
# * test_project_validators.DataManifestValidatorTest needs the two gitignored
#   evidence files under data/. It checks that the evidence is available, not
#   that the committed record is intact.
# * The two commit-reachability tests (the `!` lines below) assert ancestry,
#   which belongs to the checkout looking at an artifact, not to the artifact.
#   In a review snapshot of uncommitted work, no commit on any ref carries the
#   reviewed tree, so they fail by construction there. The content checks in the
#   same classes stay in. tests/unit/test_concordance.py explains why
#   reachability is not the reconstructability invariant.
#
# A `!` line drops one test id from a listed class. If it matches no test, the
# run is refused.
